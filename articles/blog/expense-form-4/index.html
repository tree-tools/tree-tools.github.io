GASで経費申請フォームを作ってみた（4/6）ーフォームから受け取った画像をDriveに保存するー

投稿日：2026-11-15 | カテゴリ：技術 | GASWebアプリGoogle Drive

このブログでは、Google Apps Script（GAS）で作ったツールや、作る途中で気づいたことを紹介しています。「こんな使い方もできるんだ」と、普段の作業を見直すヒントになればうれしいです。

前回は、入力された経費をスプレッドシートへ記録する仕組みを紹介しました。今回は、その経費に添付されたレシート画像をGoogleドライブへ保存する部分です。

スマホでレシートを撮影したあと、別の方法で画像を送り直さずに、申請内容と一緒に扱えるようにしました。

やりたかったこと

経費の内容だけでなく、その根拠になるレシートも、同じ申請の流れで受け付けたいと考えました。

利用者は入力画面で画像を添付し、申請を送信します。保存された画像のURLを経費の記録に残せば、確認する人はシートの行から対応するレシートを開けます。

また、複数の経費をまとめて申請する場合でも、それぞれの画像がどの経費に対応しているか分かるようにする必要がありました。

使ったロジック・ポイント

① 選んだ画像を、GASへ渡せる形にする

入力画面で画像を選んだ段階では、そのファイルを画面側で扱っている状態です。Googleドライブへの保存は、申請を送信するときに行います。

今回の実装では、画面側で画像を読み込み、Base64という文字列の形にしてGASへ渡しています。GAS側では、その文字列を画像のバイト列へ戻します。

「画面で選んだファイルを、保存処理へ受け渡すための変換」と捉えると、流れが分かりやすいと思います。

撮影した画像が大きい場合に備え、現在は4MB以上の画像をブラウザ側で自動圧縮しています。圧縮した場合は、その画像をプレビューと送信の両方に使います。申請者が別のアプリで画像を小さくしてから添付し直す手間を減らすためです。

② GAS側で画像を確認し、Driveへ保存する

GAS側では、受け取った画像の形式やサイズを確認してから保存します。画面側のチェックに加え、保存する側でもデータを確認する形です。

保存にはGoogle Drive APIを使っています。APIは、プログラムからサービスの機能を呼び出すための窓口です。GASからこの窓口へ、画像データと、ファイル名・保存先フォルダなどの情報を送ります。

保存時には、申請内容から用意したファイル名を使い、画像形式に合う拡張子を付けています。あとからフォルダを開いたときにも、ファイルを見分ける手がかりになります。

③ 複数の画像を1枚ずつ送る

経費をまとめて申請すると、添付画像も複数になることがあります。

今回は、すべての画像を一度に文字列へ変換してまとめて送る形にはせず、1枚ずつ変換して送信し、保存を確認してから次へ進む形にしました。

流れは、次のようになります。

  1. 申請内容を確認し、画像保存の準備をします。
  2. 添付画像を1枚読み込み、GASへ送信します。
  3. 保存した画像の情報を記録します。
  4. 次の画像について、同じ処理を繰り返します。
  5. 添付画像の保存がそろったら、経費をスプレッドシートへ記録します。

画面にも処理状況を表示し、利用者が画像の保存中なのか、経費の登録中なのかを確認できるようにしています。

④ 保存した画像のURLを、経費の記録につなぐ

保存処理では、作成したファイルのIDから、画像を開くためのURLを用意します。

このURLを対応する経費のデータへ組み込み、前回紹介したスプレッドシートへの記録につなげています。

画像はDriveに、購入日や金額などはシートに保存し、URLで結び付ける形です。経費を確認するときに、記録とレシートをたどれるようにしています。

⑤ 再試行するときに、保存済みの画像を確認する

通信が途中で止まった場合に備えて、画像ごとの保存状況も記録しています。

画面を開いたまま同じ申請を再試行するときは、保存済みの画像を確認し、残っている処理を進めます。また、ファイルを作る前にIDを確保しておき、保存結果の応答が届かなかった場合も、同じIDのファイルを確認できるようにしています。

画像を保存する処理だけでなく、どこまで終わったかを残すことも、申請の流れをつなぐために必要な部分でした。

各回のコード例は独立しています。順番に追加して、経費申請フォーム全体を完成させるものではありません。

以下は、画像1枚の受け渡しと保存に絞った記事用の簡略例です。運用コードの差し替え用ではありません。画像は処理済みのFileとして用意し、この例ではJPEGを使います。実装にある複数画像の順次送信、画像圧縮、申請ごとの権限確認、重複防止・再試行などは省略しています。

この簡略例は、保存するJPEG画像を5MB以下に制限しています。画像圧縮の処理は含めていません。

画面側：画像をBase64にして送る

FileReader.readAsDataURL()で画像を読み込み、先頭の形式情報を除いたBase64部分をGASへ渡します。保存が終わると、返された画像URLでPromiseが完了します。 

// 選択済み・必要に応じて圧縮済みのFileを渡します。
function sendReceiptExample(file) {
  return new Promise(function(resolve, reject) {
    const reader = new FileReader();
    reader.onerror = function() {
      reject(new Error('画像を読み込めませんでした。'));
    };
    reader.onload = function() {
      const base64 = String(reader.result).split(',')[1];
      google.script.run
        .withSuccessHandler(resolve)
        .withFailureHandler(reject)
        .saveReceiptExample({ base64: base64 });
    };
    reader.readAsDataURL(file);
  });
}

GAS側：画像へ戻し、保存したURLを返す

Utilities.base64Decode()でバイト列へ戻し、Utilities.newBlob()で保存用データを作ります。最後にDrive APIでファイルを作成し、そのIDからURLを用意します。

コードを短くするため、この例ではGASの拡張サービス「Drive API」を使います。サービスの有効化と保存先フォルダIDの設定、実行ユーザーの保存権限が必要です。運用実装は同じDrive APIをUrlFetchAppから呼んでいます。

// 記事用のJPEG保存例です。拡張サービスのDrive APIを有効にします。
function saveReceiptExample(data) {
  const bytes = Utilities.base64Decode(data.base64);
  if (!bytes.length || bytes.length > 5000000) {
    throw new Error('画像は5MB以下にしてください。');
  }
  const header = bytes.slice(0, 3).map(function(b) { return b & 255; });
  if (header[0] !== 255 || header[1] !== 216 || header[2] !== 255) {
    throw new Error('この例ではJPEG画像を使ってください。');
  }

  const blob = Utilities.newBlob(bytes, 'image/jpeg', 'レシート例.jpg');
  const saved = Drive.Files.create({
    name: blob.getName(),
    parents: ['保存先フォルダID']
  }, blob, { supportsAllDrives: true, fields: 'id' });

  return 'https://drive.google.com/file/d/' + saved.id + '/view';
}

返されたURLを経費のデータに含めれば、前回のスプレッドシートへの記録につなげられます。URLを作るだけでは画像の共有権限は変わらないため、確認する人が画像を開ける権限も必要です。

メモ・反省・次回やりたいこと

画像を添付できる画面を作るだけでなく、その画像をどこへ保存し、どの経費と組み合わせるかまで考える必要がありました。

今回のフォームでは、画像の送信・Driveへの保存・シートへの記録を分け、保存結果を次の処理へ渡しています。ひとつの長い処理として見るより、それぞれの役割を分けると流れを整理しやすくなります。

保存先は、購入した年月に対応するフォルダです。次回は、保存先のフォルダがまだ用意されていない場合に、新しいフォルダを作って管理表へ登録する仕組みを紹介します。

GASで経費申請フォームを作ってみた（6/6）ー申請後の確認メールを自動で送るー

投稿日：2026-11-19 | カテゴリ：技術 | GASWebアプリメール

このブログでは、Google Apps Script（GAS）で作ったツールや、作る途中で気づいたことを紹介しています。「こんな使い方もできるんだ」と、普段の作業を見直すヒントになればうれしいです。

前回は、購入した年月に合わせてレシート画像の保存先を用意する仕組みを紹介しました。最終回は、申請後に確認メールを送る部分です。

やりたかったこと

申請したあとに、入力した内容を手元で見返せるようにしたいと考えました。

そこで、フォームに入力されたメールアドレスへ、申請内容の控えを自動で送るようにしました。複数の経費をまとめて申請した場合も、件数・合計金額・経費ごとの明細を一つのメールで確認できます。

このメールは、申請内容を受け付けたあとの控えです。管理者による内容確認や、経費の承認を知らせるメールとは分けて考えています。

使ったロジック・ポイント

① 件名と本文のひな形をシートで管理する

メールの件名と本文は、スプレッドシートにひな形として置いています。GASは送信するときに、その内容を読み込みます。

文章の中には「{{名前}}」「{{経費件数}}」のような置き換え用の目印を入れておき、実際の申請内容を当てはめます。

定型文と申請ごとに変わる情報を分けることで、案内文を見直す際に、送信処理のコードまで書き換えずに済むようにしました。

② 複数の経費を、明細として組み立てる

申請された経費を一件ずつ取り出し、購入日・商品名・使用目的・金額などを文章にまとめます。税率ごとの金額や、レシート画像のリンク、提出状況も明細に含めています。

それぞれの明細を改行でつなげ、件数と合計金額も用意します。これらをひな形へ差し込むことで、まとめて申請した内容を一つのメールに載せています。

③ 画像保存とシートへの記録が終わってから送る

メールは、申請ボタンを押した直後に送るわけではありません。

添付画像の保存を確認し、経費をスプレッドシートへ記録してから、確認メールを送信します。GAS側では、GmailApp.sendEmail()を使っています。

宛先には、申請者がフォームに入力したメールアドレスを使います。画面に表示するGoogleアカウントの情報とは、別の情報として扱っています。

④ 経費の登録と、メールの送信結果を分ける

シートへの登録が終わったあとに、メール送信でエラーになる可能性もあります。そのため、申請の登録状況とメールの送信状況は、別々に記録しています。

メール送信に失敗しても、すでに登録した経費を取り消す処理にはしていません。申請データの保存と、メールによる通知を分けて扱う形です。

また、同じ申請の処理を再試行したときにメールが重複しないよう、送信前に処理状況を記録します。送信済みの場合や、送信結果が不明になった場合には、同じ処理から自動で再送しないようにしています。

一方で、これだけでメールの到着まで保証できるわけではありません。送信処理の結果と、受信側で実際にメールを確認できたかは区別する必要があります。

各回のコード例は独立しています。順番に追加して、経費申請フォーム全体を完成させるものではありません。

以下は、ひな形の置換から送信までを紹介する記事用の簡略例です。運用コードの差し替え用ではありません。入力チェック・権限確認・送信状況の記録・重複防止は省略しています。

ひな形の目印を申請内容へ置き換える

「{{名前}}」などの目印を探し、対応する値に置き換えます。同じ目印が複数あっても、まとめて置換する形です。

function replaceMailExample(template, values) {
  let text = template;
  Object.keys(values).forEach(function(key) {
    const value = values[key];
    text = text.split('{{' + key + '}}').join(
      value === null || value === undefined ? '' : String(value)
    );
  });
  return text;
}

明細と合計をまとめてメールを送る

シートから取得済みの件名・本文をtemplateとして渡します。例えば件名を「{{名前}}さんの経費申請控え」、本文に「{{経費件数}}」「{{申請金額合計}}」「{{経費明細}}」を入れておけば、申請ごとの内容を差し込めます。 

// 画像保存・経費登録の完了後に呼ぶ、記事用の簡略例です。
// templateにはシートから取得済みのsubject・bodyを渡します。
function sendConfirmationExample(data, template) {
  const detail = data.expenses.map(function(expense, index) {
    return [
      '【経費' + (index + 1) + '】',
      '購入日：' + expense.purchaseDate,
      '商品名：' + expense.productName,
      '金額：' + Number(expense.amount).toLocaleString('ja-JP') + '円',
      'レシート：' + (expense.receiptUrl || '画像なし')
    ].join('\n');
  }).join('\n\n');

  const total = data.expenses.reduce(function(sum, expense) {
    return sum + Number(expense.amount);
  }, 0);
  const values = {
    名前: data.name,
    経費件数: data.expenses.length,
    申請金額合計: total.toLocaleString('ja-JP') + '円',
    経費明細: detail
  };
  const subject = replaceMailExample(template.subject, values);
  const body = replaceMailExample(template.body, values);
  GmailApp.sendEmail(data.email, subject, body);
}

map()で明細を作り、reduce()で金額を合計しています。記事では明細項目を一部に絞っていますが、運用実装では使用目的・税率ごとの金額・提出状況なども含めています。

この関数は経費の登録完了後に呼ぶ前提です。例だけでは登録の完了確認や重複送信の防止は行わないため、運用コードへそのまま追加するものではありません。実行すると指定した宛先へ送信するため、試す場合は自分のテスト用アドレスを使います。

メモ・反省・次回やりたいこと

全6回を通して、入力画面・スプレッドシート・Googleドライブ・メールをつなぐ経費申請フォームを紹介しました。

画面から入力できるようにするだけでなく、入力の誤りを知らせること、画像と経費を対応させること、保存先を用意すること、申請後の控えを残すことまで、一連の流れとして考えました。

今回の仕組みでも、レシートと申請内容が本当に一致しているかは、人が確認する必要があります。自動化する部分と、確認する人に残す部分を分けておくことも大切だと感じました。

今後も、実際の作業で手間になっている部分を見ながら、必要な処理を少しずつつなげていきたいと思います。

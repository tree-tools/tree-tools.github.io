やりたかったこと

前回は、レシート画像と申請内容をまとめて表示する確認画面の概要を紹介しました。

確認作業は、スプレッドシートのリストを見ているところから始まります。その流れで確認画面を開けるように、シートに処理の入口を用意したいと考えました。

そこで追加したのが、「経費確認」メニューの「現在のシートを確認」という項目です。作業したい月のシートを開いてから選ぶと、そのシートを対象に確認を始められます。

使ったロジック・ポイント

① カスタムメニューから、GASの関数を呼び出す

GASでは、スプレッドシートのメニューバーに独自のメニューを追加できます。これを「カスタムメニュー」と呼びます。

項目には実行する関数を結び付けられるので、使う人は関数名を覚えたり、スクリプトエディタを開いて実行する関数を選んだりせずに操作できます。

今回は、「現在のシートを確認」という項目から、確認画面を開く関数を呼び出す形にしました。メニューは作業を選ぶ入口で、画像の表示や修正内容の保存は、呼び出した先の処理が担当します。

② ファイルを開いたときに、メニューを用意する

メニュー作成では、createMenu()でメニュー名を決め、addItem()で項目名と呼び出す関数名を指定し、addToUi()で画面に追加します。

ファイルを開いたときにメニューを表示するには、onOpen()という関数にメニューを作る処理を書きます。

ここで用意するのは、作業を始めるための入口です。経費の確認は、利用者がメニューの項目を選んだところから始める形にしています。

なお、ここで紹介するのは、対象のスプレッドシートに紐付いたGASで作るメニューです。PCのブラウザでシートを操作する使い方を想定しています。

③ 項目名で、対象と作業が伝わるようにする

今回は月ごとにシートを作るので、項目名を「現在のシートを確認」としました。どのシートが対象なのか、何をする操作なのかが名前から分かるようにするためです。

ただし、項目名を付けるだけで対象が決まるわけではありません。開いているシートを使う、選択した範囲を使うなど、実際の処理も項目名に合うように用意します。

▶ GASの認証ガイド

以下は、「経費確認」メニューを追加し、項目を選ぶと現在開いているシート名をメッセージで表示する最小例です。経費確認画面そのものを再現するコードではなく、メニューと関数のつながりを試すためのものです。

              function onOpen() {
  SpreadsheetApp.getUi()
    .createMenu('経費確認')
    .addItem('現在のシートを確認', 'showReviewTarget')
    .addToUi();
}

function showReviewTarget() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
  SpreadsheetApp.getUi().alert('確認対象：' + sheet.getName());
}

対象のスプレッドシートから「拡張機能 → Apps Script」を開き、コードを保存したあと、スプレッドシートを開き直すとメニューが追加されます。初回実行時に権限の承認を求められた場合は、内容を確認して進めます。

addItem()の1つ目は画面に表示する項目名、2つ目は呼び出す関数名です。ここでは「現在のシートを確認」を選ぶと、showReviewTarget()が実行されます。

実際の経費確認画面では、呼び出した関数からダイアログを開く処理につなげています。メニューの入口を保ったまま、その先の処理を用途に合わせて変えられます。

すでにonOpen()がある場合は、同じ名前の関数を増やさず、既存の関数へメニュー作成部分を組み込みます。

メモ・ほかにも使えそうなこと

作った処理をメニューから呼び出せるようにすると、いつも使っているシートを、そのまま作業の入口にできます。

例えば、月のデータを集計する、選択した内容から帳票を作る、入力内容をまとめてチェックする、といった処理にも使えそうです。これらは今回追加した機能ではなく、応用のアイデアです。

GASで何かを自動化できたら、「どこから呼び出すと使いやすいか」も考えてみると、操作する人に合わせた使い方が見つかりそうです。
